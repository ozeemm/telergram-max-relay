# Telegram ↔ MAX relay

Приложение пересылает текстовые сообщения между одним разрешённым пользователем Telegram и одним контактом MAX через GREEN-API. Оба направления работают внутри одного контейнера: Telegram опрашивается через Bot API, а уведомления GREEN-API забираются из очереди уведомлений.

## Настройка

1. Создайте Telegram-бота через BotFather и получите числовой Telegram user ID, которому разрешено пользоваться пересылкой.
2. Создайте/подключите MAX-инстанс в GREEN-API и получите ID чата выбранного собеседника.
3. Скопируйте `.env.example` в `.env`, затем заполните значения:

   ```dotenv
   TELEGRAM_BOT_TOKEN=         # секрет Telegram-бота
   TELEGRAM_USER_ID=           # числовой ID разрешённого пользователя
   GREEN_API_INSTANCE_ID=      # ID инстанса GREEN-API для MAX
   GREEN_API_TOKEN=            # секрет GREEN-API
   MAX_CHAT_ID=                # ID чата выбранного собеседника MAX
   ```

4. Запустите контейнер:

   ```powershell
   docker compose up --build -d
   docker compose logs -f
   ```

## Алгоритм

### Telegram → MAX

1. Приложение получает обновление Telegram методом long polling.
2. Обработчик допускает только личные сообщения от Telegram ID, указанного в `TELEGRAM_USER_ID`.
3. Текст передаётся GREEN-API методом `sendMessage` в заданный `MAX_CHAT_ID`.
4. При ошибке отправки она записывается в лог без текста сообщения и секретов, а отправителю возвращается уведомление об ошибке.

### MAX → Telegram

1. Фоновая задача получает следующее уведомление GREEN-API методом `receiveNotification`.
2. Обрабатываются только входящие текстовые сообщения от настроенного MAX-чата; события от других чатов и неподдерживаемые типы сообщений не пересылаются.
3. Текст отправляется в личный чат Telegram указанного пользователя. Длинные сообщения делятся на части.
4. После успешной доставки уведомление отмечается в SQLite и подтверждается через `deleteNotification`. Если отправка не удалась, уведомление не подтверждается и будет обработано повторно.

Дедупликация по `receiptId` сохраняется в `/data/state.sqlite3`. Если сбой произойдёт между фактической отправкой в Telegram и записью подтверждения в SQLite, возможна повторная доставка: гарантировать exactly-once между двумя внешними API нельзя.

## Ограничения первой версии

- Только один Telegram-пользователь и один контакт MAX.
- Поддерживаются текстовые сообщения; медиа, документы, голосовые и пересылка исходных метаданных пока не реализованы.
- На Telegram-боте используется polling; отдельный публичный веб-сервер и отдельные сервисы для платформ не нужны.
- Для GREEN-API используется v3 API. Методы и формат уведомлений основаны на официальном клиенте GREEN-API для MAX: [max-api-client-python](https://github.com/green-api/max-api-client-python).
